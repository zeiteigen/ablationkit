# Release qualification

v1.0 ships when every spec §15 acceptance criterion passes or has a documented exception the researcher accepted (spec §14 release gate).

- [Acceptance report](acceptance-report.md): generated by `bun run acceptance` from `scripts/acceptance-criteria.ts`, which names each criterion's owning stage and its automated evidence. Each run records the commit, the suites it ran, and per criterion pass, fail, not run, partial or not started. Evidence in a suite that was not run is never counted as passing.
- [MLflow feature compatibility matrix](../api/mlflow-compatibility.md) (criterion 18).
- [Security threat map](../security/threat-map.md): each threat, its control and level, and the tests that prove it (ADR 0027).
- Opt-in suites that are not in CI because they download large wheels: `test:extensions` (a real pinned wheel), `test:torch` (CPU torch). Run them with `bun run acceptance --real` before tagging.
- Packaging (ADR 0028): `bun run package -- --out DIR [--tar FILE]` stages a release, `scripts/packaging/install.sh` installs it per user, and `scripts/packaging/aur/PKGBUILD` builds the Arch package from `bun run package -- --source-tarball FILE`. `bun run test:package` (opt-in) boots a coordinator from a read-only staged tree, runs a job and an extension build from it, exercises the install script and builds the AUR package.
