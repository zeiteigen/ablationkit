Start here

AblationKit brings your experiments and their explanations together. Use the UI to read research, inspect runs, compare results, and manage compute. Your coding agent works in its own harness and reports into AblationKit.

What do you want to do?

01 · Set up

Track your first project

Register a checkout, connect an agent, and launch a small experiment.

02 · Understand

Catch up on the research

Start with Standing, then read the notebooks and their evidence.

03 · Experiment

Compare alternatives

Inspect jobs, select runs, and compare metrics against a baseline.

04 · Evaluate

Improve an LLM or RAG system

Follow traces, pin prompt versions, and evaluate a golden set.

How the pieces fit

  1. Checkout Your code and data
  2. Job A command and its attempts
  3. Run Metrics, parameters, artifacts
  4. Vault What the evidence means

A job executes work; a run records measurements. A study groups variants around a question. The vault holds atomic notes, composed into notebooks, with a ledger of the project's current standing.

Find your way around

Global and project navigation
Place Use it for
Home Each project's bottom line, unread ledger lines and last session; running jobs and items needing attention
A project's Overview Where it stands, in brief, and what the agents did: their sessions, tasks, and running jobs
Standing / Notebooks Conclusions, open questions, and the explanations behind them; Notebooks · Tree · Library in the trail
Runs Runs, Studies, and Jobs; Compare, Entrypoints, and Experiments under More ▾
More (in a project) Data & Evals and Models until the project uses them, backend pages hidden by the task profiles, and the original records (Knowledge, Tasks, Review)
Compute Usage over a period, agent compute against each project's limit; targets and compute weights folded below
Settings / Docs (bottom of the sidebar) Settings has three tabs: Preferences (sign-in, notifications), Agent sessions, and System (tracking health, delivery, backups, build). Docs is this guide

Use Ctrl + K (or ⌘ + K ) for the command palette; inside a project it leads with Standing, Notebooks, finding a note, the Library, and the Tree, and its last row searches the notes for what you typed. Every page starts with a trail that says where you are (project › section › page) and holds the page's actions at its right. On a phone, the sidebar is behind the Menu button in the header, which names where you are. Backend pages may appear under More depending on the project's task profiles.

Reusable documentation

Open index.html in this directory to read the guide independently, even offline. Copy the HTML pages and stylesheet from the docs/guide/ directory to a static host to publish it. The UI renders this same HTML directly. The HTML and shared stylesheet live in docs/guide/. The reusable renderer in apps/web/src/guide/ depends only on React and these files, independently of the application shell.
