LLM and RAG research

Use the bundled LLM backend to connect an answer to its trace, prompt version, evaluation examples, and saved evidence.

Open the LLM page

Choose LLM in the project navigation. If it is under More, enable a relevant task profile in Project settings. The bundled backend must be enabled for the project; its controls live with Extensions.

Follow a failing answer

  1. Trace Find the failing call
  2. Spans Inspect retrieval and tools
  3. Example Capture the expected result
  4. Evaluation Test the proposed change

In Traces , open the span tree and waterfall. Inspect inputs, outputs, retrieval results, tool calls, errors, and feedback where recorded. For RAG, follow the query through retrieval, reranking, and generation. An unrecorded field is missing evidence; it does not establish that the pipeline skipped that step.

Compare prompts on the same inputs

  1. Prompts: inspect versions, aliases, and diffs. Pin versions for comparisons so a moving alias cannot silently change the experiment.
  2. Golden sets: create or select a versioned set of inputs and expectations. JSONL paths are relative to the project checkout. Include edge cases and representative failures.
  3. Evaluations → New evaluation: select the golden set, add targets (recorded runs or prompt/model settings), and choose scorers. Optional judge scorers require their model configuration.
  4. Run evaluation: inspect per-example results as well as aggregates. Follow failing examples back to their traces before deciding what to change.
What to ask an agent to record

Ask it to pin prompt versions, model and decoding settings, golden-set version, and scorers; summarize failure clusters; link each conclusion to examples and traces; and explain what the comparison does and does not establish.

Explore before running a full evaluation

The Playground tries prompt targets on individual inputs or a golden set. Choose Save as evidence for results you want to retain. Inspect them under Evidence. Trace storage depends on the capture policy.

Check Data controls first

Review capture, retention, provider, and egress settings before sending inputs or collecting traces. An evaluation or judge call can use an external model provider. Choose inputs and settings appropriate to your project.
