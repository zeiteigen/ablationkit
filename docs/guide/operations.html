Manage your workspace

Keep execution, tracking delivery, and research records healthy without confusing their states.

Set agent permissions and compute limits

Open Project settings → Agents . Review the action policy for local jobs, remote jobs, and deployments, and the agent sessions that reported into the project. Preview changes before saving a new policy revision. Set the project's agent compute limit in weighted hours.

On Compute , inspect agent usage; open Compute weights to set per-target weights. The weights determine how execution time counts toward the agent limit; they are not a currency price. A session identifies the agent and attributes its work. Its Git access and sandbox come from the harness.

Read the enforcement status

Resource limits can be advisory when the process supervisor uses its direct-mode fallback. A job's page reports enforcement, and so does Compute → Targets → This workstation; the status bar's health item says it on hover. Do not interpret a displayed limit as a guarantee that every process is constrained.

Use remote compute

The CLI sets up SSH, Slurm, Runpod, and Colab targets. Start with ablationkit target list and use ablationkit help for target-specific setup. Once configured, choose the remote target when submitting a job.

A remote attempt executes a staged bundle of a pinned commit and uploads results. Use Compute and job details to follow it. Offline reconciliation may be needed after a connection interruption; a remote drain delivers the leftover spool and does not rerun the experiment.

Check tracking before repeating work

The status bar at the bottom of every page shows one health item, the coordinator and MLflow, which opens Settings → System; hover it for the rest. It adds an item only when something needs a look: a delivery backlog or failure, remote work, running jobs, live updates reconnecting, safe mode, or a modified build.

Symptom Next step
Job finished, results missing Inspect its console and delivery state. Check Settings → System for MLflow health and the delivery backlog.
Tracking delivery failed Use tracking diagnostics and retry the failed operation once the underlying problem is fixed.
Moved checkout Use project remap, then project doctor to check the registered path.
Signed out Run ablationkit ui on the workstation for a new one-time sign-in link.
Diagnostic commands 
ablationkit tracking doctor
ablationkit tracking status
ablationkit tracking outbox --failed
ablationkit project doctor --project PROJECT_ID

Back up and recover

Create a backup before changing storage or moving the coordinator. Settings → System shows backups and recovery controls. 

ablationkit backup create
ablationkit backup list
ablationkit backup verify BACKUP_ID

Replace BACKUP_ID with an ID from the list. Restore and coordinator moves require the coordinator to be stopped. Consult ablationkit help for restore paths and project remapping options. Do not treat vault export as a full backup.

Manage extensions and sessions

Project settings → Extensions contains build, enable, and rollback controls for project extensions and bundled backends. Read their capability and trust information before enabling them. If an extension prevents startup, restart with ablationkit coordinator restart --safe-mode to boot with extensions inactive.

In Settings → Agent sessions , inspect the harness, label, directory, last use, and attributed work. End session revokes its token. Machine-wide notification and authentication controls are under Settings → Preferences, and the coordinator's health under Settings → System (also at /system ).
