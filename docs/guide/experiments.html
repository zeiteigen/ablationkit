Run and compare

Use jobs to execute work, runs to inspect measurements, and studies to compare variants around a question.

Launch and follow a job

Open Runs → Jobs → Launch job . Enter a command, environment, relative working directory, and resource limits. Optionally associate a run name, study, and variant, and configure metrics-file collection and artifact globs.

Commands run directly

The launch command is not interpreted by a shell. Put pipelines, redirections, or multi-step setup in a script and run that script.

The job detail contains attempts and console output. An attempt describes an execution; its status, logs, and delivery state help distinguish a process failure from a tracking failure. Remote delivery may finish after execution.

Find the runs that answer your question

On Runs, filter by status, study, variant, or MLflow filter expression (on a phone, open Filter first). For example: 

metrics.loss < 0.5 and params.lr = '0.01'

The table's metric columns start with the metrics your studies decide on, then held-out metrics ( validation/ , eval/ ), then the rest. Each run's description is cut to one line; hover it for the whole. The Sync and Duration columns appear only when their values differ between runs.

Open a run for its description, metrics and curves, parameters, tags, system metrics, and artifacts. Use the artifact browser for saved outputs. What the run came from and what cites it (its lineage) is folded under Provenance: lineage at the bottom of the page.

Compare against a baseline

  1. Select 2–20 runs in Runs and choose Compare selected , or open Runs → More ▾ → Compare and pick them there. Entrypoints (MLproject) and Experiments (MLflow experiments) are under the same More ▾ menu.
  2. Choose a baseline. Inspect parameters and latest metrics, enable only rows that differ , and use metric overlays to check how the runs evolved.
  3. Check the study's metric goals before interpreting “best.” A lower loss and a higher accuracy have different directions.
  4. Export the table as CSV or runs as CSV/JSON when you need the underlying values elsewhere.

Latest metric values are a comparison point, not a substitute for reading the curves. Differences in inputs, splits, or training budgets can change what a result means.

Organize repeatable comparisons

In Runs → Studies , create a study with its question, protocol, variants, baseline, and metric goals. Associate subsequent jobs with those variants. Read the study's explanation alongside its runs; variant curves show the newest run for each variant. A study's Export ▾ menu downloads its table or its runs as CSV. A study's page leads with its results: the table (the metrics that decide the study first, then the parameters that differ), the curves, then what it tests (each claim of the vault resting on the study, with its standing, and the original hypotheses beneath), the reading, and the design and every run by variant folded under Design and runs .

Datasets, models, and inference

Workflow Where to go and what to supply
Classical evaluation Data & Evals → Classical evaluations. Supply the model, a checkout-relative dataset path, target column, split, and optional validation thresholds. Read metrics and diagnostics.
Model registry Models → Registry. Inspect logged models, registered versions, and aliases. Until the project logs a model or runs an evaluation, Data & Evals and Models are under More in the project navigation; Registry, Inference, and Demos may initially sit under the Models tabs' More ▾.
Try a model Models → Inference. Select a model and adapter inputs, or paste JSON. Use One-shot, Session, or Compare mode and acknowledge model trust when requested.
Keep an inference result Choose Save as evidence. Exploratory inference is transient; saved evidence preserves the result for later reading.
